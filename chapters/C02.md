## Question: what does it mean for an algorithm to be fast?

Two people are given a numerical problem. One has an input consisting of a five-digit number; the other has a million-digit number. Comparing their running times without first specifying how inputs are written would be nearly meaningless.

Complexity theory measures resources against the **length of the encoded input**, not necessarily against the value of a number appearing in that input. The choice is especially important when numbers are encoded in binary: a short string can denote an enormous quantity.

C01 distinguished *what* an algorithm must output. We now need a language for asking *how its resource use grows*.

## 1. The input is a finite string

Fix a binary encoding of problem instances. For an input $x\in\{0,1\}^*$, write $n=|x|$ for the number of bits in the encoding. A particular algorithm $A$ has a running-time function $T_A(n)$ that bounds the number of elementary machine steps on the **worst-case** valid encoded inputs of length $n$. If no such inputs exist at a length, we can use a harmless convention for that length.

**Example: a large integer with a small encoding.** The positive integer $N=2^k$ is written in conventional binary as a 1 followed by $k$ zeros, so its encoding length is $k+1$, not $2^k$. An algorithm performing $N$ elementary iterations therefore takes exponentially many iterations in the length of its binary input. Merely saying its running time is "linear in $N$" conceals this distinction.

A representation can alter the question. Writing a positive integer $N$ in unary as $N$ tally marks requires $N$ symbols. A process taking $O(N)$ steps is linear in the **unary** input length but exponential in the length of the usual binary representation for inputs near powers of two. The apparent difference is not a contradiction: the encoded decision problems are different languages.

> **Encoding principle.** Polynomial-time changes of representation preserve membership in P when each representation can be translated to the other in polynomial time. This is not a license to replace ordinary binary inputs by exponentially longer unary encodings without accounting for conversion cost.

## 2. Why a mathematical cost model is necessary

We need a precise notion of an elementary operation. A standard model is a deterministic multi-tape Turing machine with a finite alphabet and a read-only input, in which each step changes only a bounded amount of local information. Other conventional sequential models can simulate one another with at most polynomial overhead under standard bounded-operation assumptions.

One should be careful with *unit-cost* machine models. If an abstract instruction can multiply integers with trillions of digits in one step at constant price, then the model is hiding real computational work. A **bit-cost model** charges for operations according to the number of bits they manipulate. For the present Atlas, statements about P use standard Turing-machine/bit-complexity conventions unless a different cost is explicitly named.

A complexity claim is therefore shorthand for three linked choices:

- a problem contract (decision, search, optimization, counting, and so on);
- an encoding of its finite instances;
- a computational model and measured resource.

A claim that omits any of these may still be useful engineering shorthand, but it is not yet a precise theorem.

## 3. Worst case, best case, and promises

**Worst-case time** bounds every applicable input of a given length. This does not mean every input actually consumes that much time. A graph-search routine may finish immediately when its target is the start vertex yet require many steps on a large disconnected graph.

**Average-case time** requires a probability distribution on inputs: "the average" is undefined until one says what is sampled. **Expected randomized running time** instead averages over the algorithm's own random bits, for a specified input; these are different concepts.

**Promise problems** add a further qualification. If a correctness guarantee covers only the promise set, complexity bounds and correctness are normally stated relative to that set. One may not silently use a promise algorithm as a total decider on arbitrary strings.

We will develop randomness and average-case behavior in later chapters. Here the default measure is worst-case running time.

## 4. Big-O is an eventual bound

Let $f,g:\mathbb N\to[0,\infty)$ and assume $g(n)>0$ for all sufficiently large $n$.

**Definition.** $f(n)=O(g(n))$ when there exist constants $C>0$ and $n_0$ such that $f(n)\le Cg(n)$ whenever $n\ge n_0$.

**Definition.** $f(n)=\Omega(g(n))$ when there exist $c>0$ and $n_0$ such that $f(n)\ge cg(n)$ whenever $n\ge n_0$.

**Definition.** $f(n)=\Theta(g(n))$ if both bounds hold.

These statements describe eventual growth rather than benchmark timing. Hidden constants and the threshold $n_0$ can be enormous.

**Worked bound.** Let $T(n)=3n^2+5n+7$. For $n\ge1$, we have $5n\le5n^2$ and $7\le7n^2$, hence $T(n)\le15n^2$. Also $T(n)\ge3n^2$. Thus $T(n)=\Theta(n^2)$, with both constants exhibited.

A function may have several valid upper bounds. For example, $n^2=O(n^3)$, but $\Theta(n^2)$ is more informative when the intended comparison is to quadratic growth. An $O$ statement alone is **not** a matching lower bound.

## 5. A hierarchy of familiar growth rates

For fixed constants $a>1$ and $k>0$,

$$
\log n=o(n^k), \qquad n^k=o(a^n).
$$

Here $f=o(g)$ means $f(n)/g(n)\to0$ as $n\to\infty$. Informally, fixed-degree polynomials eventually outgrow logarithms, and fixed-base exponentials eventually outgrow any fixed-degree polynomial.

For every two fixed bases $a,b>1$, logarithms differ only by a constant factor:

$$
\log_a n=\frac{\log_b n}{\log_b a}.
$$

Consequently, changing the logarithm base does not change its Big-O class. In contrast, changing the exponent of a polynomial matters: $n^{10}$ is still polynomial, but it may be much larger than $n^2$ for practical inputs.

Consider the following table. Its entries count **abstract steps**, not seconds on a device.

| Input length $n$ | $n^2$ | $2^n$ |
|---:|---:|---:|
| 5 | 25 | 32 |
| 10 | 100 | 1,024 |
| 20 | 400 | 1,048,576 |
| 30 | 900 | 1,073,741,824 |

A larger input does not always mean that the actual runtime of every algorithm increases. The functions are illustrative *bounds*; real procedures can terminate early.

## 6. Polynomial time: a robust mathematical threshold

A deterministic procedure is **polynomial-time** when its worst-case running time is bounded above by $O(n^k)$ for some fixed constant $k$, where $n$ is the encoded input length. "Fixed" means independent of the particular input. An algorithm with runtime $n^{\log n}$ does **not** fit this definition, because the exponent grows with $n$.

Why single out polynomial bounds? A useful reason is closure under composition. Suppose $f$ maps binary strings to binary strings in time $O(n^a)$, and a subsequent procedure takes $O(m^b)$ on its length-$m$ input. Because writing the output of $f$ takes time, $|f(x)|=O(n^a)$. The combined time is bounded by

$$
O(n^a)+O((n^a)^b)=O(n^{\max(a,ab)}),
$$

which is polynomial for fixed $a,b$. The stronger statement in a particular model may yield smaller exponents; the displayed estimate suffices for closure.

This matters for reductions, which C05 will formalize. Translating the input and applying an efficient solver does not silently require a superpolynomial amount of time if both operations have the stated bounds.

## 7. Polynomial in a number versus polynomial in its digits

Consider the standard dynamic-programming formulation of the knapsack problem. A table indexed by a numeric capacity $W$ may require $O(mW)$ entries for $m$ items. If $W$ is binary encoded, its bit length is $\lfloor\log_2W\rfloor+1$ for $W\ge1$. Therefore $O(mW)$ need not be polynomial in the **encoded input length**. Such running times are called *pseudopolynomial*.

This is not a claim that every knapsack algorithm requires so much time, nor that the problem is outside P. It illustrates why the size of a numerical parameter and the length of its written representation cannot be interchanged.

The same caution applies when an algorithm loops a number of times equal to an input integer. A loop counted in a numerical magnitude may hide exponential growth relative to the number's digits.

## 8. What an upper bound does not establish

- An algorithm with polynomial running time is not necessarily practical. A bound such as $n^{100}$ can be huge.
- A proved exponential upper bound does not imply the problem needs exponential time; another algorithm might be faster.
- A failed search for an efficient algorithm is not a lower-bound proof.
- A running-time result for **one algorithm** is not automatically a lower bound for **every** possible algorithm solving the problem.
- A faster machine changes elapsed seconds but not the formal asymptotic claim within the chosen model.

Later chapters will separate algorithmic upper bounds, class inclusions, provable separations, and open conjectures. This chapter establishes the vocabulary needed not to confuse them.

## Exercises

1. Write $2^{12}$ in binary. How many bits does it use? How many iterations does a loop of length $2^{12}$ make?
2. Prove directly that $4n^3+9n+2=\Theta(n^3)$ using explicit constants and a threshold.
3. Explain why measuring time as a function of the numerical value $N$ rather than the bit length of $N$ can mislead for a binary-encoded input.
4. Suppose $f$ takes $O(n^2)$ time and produces an output consumed by a procedure taking $O(m^3)$ time. Derive a valid polynomial upper bound for the composed procedure.
5. Explain why an $O(mW)$ knapsack algorithm can be pseudopolynomial even though both $m$ and $W$ are finite.
6. Give an example where the worst case and the runtime on an easy input are very different.
7. Is $n^{\log n}$ polynomially bounded? Justify by comparing it with $n^k$ for any fixed $k$.
