# C10 — Space: How Much Must a Computation Remember?

**Status:** Expanded manuscript candidate; mathematical and pedagogical review pending.  
**Prerequisites:** C01–C05, with C04's verifier interpretation of NP.

## Question: what if we limit memory rather than time?

Imagine a traveler crossing a maze who can make millions of moves while keeping only a small notebook. The number of moves is a **time** cost; the maximum amount written in the notebook at any moment is a **space** cost. Erasing and reusing pages can keep space small without making the route short.

For a computer, space is not the size of every transient intermediate value summed over all steps. It is how much working information is simultaneously available. This makes it a distinct resource, with its own classes and proof techniques.

## 1. A precise space measure

Use a deterministic Turing machine with a read-only input tape and one or more read-write work tapes. On an input $x$ of length $n$, its *work space* is the number of distinct work-tape cells visited. An $s(n)$-space machine uses at most $O(s(n))$ such cells on every length-$n$ input. Input symbols themselves are not charged, but positions, control state and scratch memory follow the model's specified accounting conventions.

Let $DSPACE(s(n))$ denote languages decided using deterministic $O(s(n))$ space. Define

$
PSPACE=\bigcup_{k\ge1} DSPACE(n^k).
$

Likewise $NSPACE(s(n))$ allows nondeterministic branching while retaining the same space accounting on every computation path, and $NPSPACE$ is the union of nondeterministic polynomial-space classes. We assume standard constructibility conditions whenever theorems require them.

## 2. A counter that runs a very long time

Take a binary integer $N=2^k$, represented in $k+1$ bits. Starting at zero, increment a binary counter until it reaches $N-1$. This performs $2^k$ iterations but stores a counter using $O(k)$ bits. It is a concrete example that **exponential time can coexist with linear space**.

Do not interpret this as a lower bound: someone asked to compute the final value might devise a more direct algorithm. The point is about resource usage *of this particular computation*, not intrinsic task difficulty.

## 3. Proven containments

**Theorem. $P\subseteq PSPACE$.**

**Proof.** On every execution step, a Turing machine can visit at most a constant number of previously unvisited work-tape cells. Thus a deterministic algorithm that takes $O(n^c)$ time visits $O(n^c)$ cells. Polynomial-time decision languages therefore belong to PSPACE. $\square$

**Proposition. $NP\subseteq NPSPACE$.** Each accepting or rejecting branch of a polynomial-time nondeterministic machine can touch only polynomially many work cells. This observation is independent of whether that machine has exponentially many possible branches.

The more surprising bridge from nondeterministic to deterministic space is Savitch's theorem.

## 4. Configuration graphs

A **configuration** records enough information to resume a machine: current control state, work-tape contents within the space bound, work-tape head positions, and the location on the read-only input. With $s(n)\ge\log n$, these configurations can be encoded in $O(s(n))$ bits for a fixed finite-tape machine, yielding at most

$
N=2^{O(s(n))}
$

different configurations.

Nondeterministic acceptance of an input is therefore equivalent to reachability in a finite directed graph whose vertices are machine configurations and whose edges are legal one-step transitions. A graph may have exponentially many vertices without any single configuration being exponentially long.

**Finite path observation.** If there is a path from start configuration to an accepting configuration, there is a simple path of fewer than $N$ edges. Removing cycles from a walk preserves the endpoints. Thus we need to test reachability only up to an exponentially large bound, not simulate all paths forever.

## 5. Savitch's theorem, with the recurrence visible

**Theorem (Savitch).** If $s(n)\ge\log n$ is space-constructible, then

$
NSPACE(s(n))\subseteq DSPACE(s(n)^2).
$

**Proof sketch with resource accounting.** Define $R(u,v,j)$ to mean that a configuration $v$ is reachable from configuration $u$ in **at most $2^j$ steps**. For $j=0$, check whether $u=v$ or whether one legal transition connects $u$ to $v$. For $j>0$, search through all possible midpoint configurations $m$, accepting if

$
R(u,m,j-1)\ \land\ R(m,v,j-1).
$

A path of at most $2^j$ edges can be broken into two pieces of at most $2^{j-1}$ edges each; a shorter path can use its endpoint as a midpoint where needed. Conversely, concatenating two such subpaths produces a path of at most $2^j$ edges. That proves the recurrence's correctness.

There are $2^{O(s(n))}$ configurations, so it suffices to choose $j=O(s(n))$. The recursive depth is $O(s(n))$. At each level, keep a constant number of $O(s(n))$-bit configurations and counters while reusing space after a recursive call. Total work space is therefore $O(s(n)^2)$. The algorithm may re-examine many midpoints and use enormous time; Savitch's theorem claims **space**, not time, efficiency.

The proof can be made fully formal by encoding configurations, midpoint enumeration, and the base-case transition test. This chapter provides the structural core; a technical appendix may supply the full machine model.

**Corollary.** $NPSPACE=PSPACE$. Indeed, the theorem turns nondeterministic polynomial space into deterministic polynomial space, while every deterministic computation is also nondeterministic. Consequently

$
P\subseteq NP\subseteq PSPACE.
$

**Epistemic caution:** None of these inclusions is known to be strict. Do not interpret a nested diagram as evidence for $P\ne NP$ or $NP\ne PSPACE$.

## 6. Reachability and reuse

Consider directed reachability: from a given vertex $s$, is there a path to $t$? Standard graph search can mark reached vertices and uses polynomial space relative to the input graph. A different algorithm can explore possible paths in a depth-first manner and overwrite its working representation when backtracking. Either way, space counts **maximum concurrent state**, not the number of states explored over the full run.

Savitch's algorithm generalizes this idea: instead of saving an entire witness path, it asks recursively whether *some midpoint* divides a shorter reachability question into two. C11 will use quantified Boolean formulas to give a canonical PSPACE-complete setting; we are not assuming that completeness result here.

## 7. Common mistakes

**“Long computations need large memories.”** Not when memory can be overwritten. A fixed-size binary counter may be updated very many times.

**“PSPACE is strictly harder than NP.”** The proved result is containment $NP\subseteq PSPACE$, not separation.

**“The configuration graph is exponentially large, so Savitch needs exponential space.”** Its vertices are considered one at a time; recursion depth and per-frame storage control the space.

**“Polynomial space implies practical solvability.”** An algorithm consuming an astronomical number of steps can satisfy a polynomial-space bound.

## Exercises

1. Give a counting program that takes $2^{100}$ increments but keeps $O(100)$ bits of counter space. Specify what is counted as input and work memory.
2. Prove $P\subseteq PSPACE$ directly from the number of machine steps.
3. Explain why the number of configurations is exponential in $s(n)$ even though each configuration has $O(s(n))$ bits.
4. Expand $R(u,v,2)$ using the midpoint recurrence. Explain the base case and why using *at most* $2^j$ steps matters.
5. Estimate the recursion depth when the configuration graph has $2^{100}$ nodes, and compare it to the number of nodes.
6. Identify the unjustified assertion in “Savitch proves $NP$ is strictly contained in $PSPACE$.”
