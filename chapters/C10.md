# C10 — Space as a Computational Resource

**Status:** Editorial draft; independent review outstanding.

## Question

How much information must a computation hold at one time? Time measures steps; space measures workspace cells used, which can be reused across many steps.

With a read-only input and read-write work tape, DSPACE(s(n)) is the collection of decision languages solvable by deterministic machines using O(s(n)) work cells. Define

[
PSPACE=igcup_{kge1}DSPACE(n^k).
]

## Worked example: counting

Given a binary integer (N=2^k), a program can count from 0 to (N-1) in (2^k) increments using a (k)-bit counter. Long runtime need not imply long memory. This example establishes a possible time-space tradeoff, not a lower bound on any particular task.

## Containments

**Theorem.** (Psubseteq PSPACE). A machine that halts in polynomial time cannot visit more work cells than the number of steps it takes.

**Theorem (Savitch).** For space-constructible (s(n)gelog n),

[
NSPACE(s(n))subseteq DSPACE(s(n)^2).
]

**Proof sketch.** A configuration of an (s(n))-space machine stores its control state, work tape and head positions. There are at most (2^{O(s(n))}) configurations. To test reachability between two configurations, recursively search for a midpoint and halve the allowed path length. Depth is O(s(n)), with O(s(n)) bits of per-level state, for O(s(n)^2) workspace. Repeatedly trying candidate midpoints can be expensive in time.

Since polynomial space squared is polynomial, (NPSPACE=PSPACE). A nondeterministic polynomial-time machine uses polynomial space, so (NPsubseteq PSPACE). Whether (P=NP), (NP=PSPACE), or either inclusion is strict is open.

## Boundary

A configuration graph may contain exponentially many vertices, but a machine need not store all of them simultaneously. Counting configurations must not be conflated with workspace occupation.
