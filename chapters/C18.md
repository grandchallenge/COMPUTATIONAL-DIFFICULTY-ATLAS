# C18 — Approximation: How Close Is Close Enough?

**Status:** Editorial candidate; review and figures pending.
**Prerequisites:** C01, C05, C06.

## Question: can we give up exact optimality without giving up guarantees?

A near-optimal road tour might suffice. Approximation requires a feasible answer with a quantified guarantee, not merely a plausible guess.

## Section 1 — Objective and ratio

For nonnegative costs, a nonempty feasible set and attained minimum OPT, a ratio-$\rho$ minimization algorithm returns feasible $s$ with $c(x,s)\le \rho\,\mathrm{OPT}(x)$, $\rho\ge1$. For maximization use $c(x,s)\ge\mathrm{OPT}(x)/\rho$. This handles zero optima without division by zero. A threshold decision oracle can locate an integer optimum by binary search if a containing interval of polynomial bit length is known. Extracting a witness needs a separate construction; an approximate cost does not generally answer an exact threshold.

## Section 2 — A proved 2-approximation

For minimum vertex cover, repeatedly select an edge, add both endpoints to $S$, and remove all incident edges. Selected edges form a maximal matching $M$. Every original edge meets $S$, otherwise it could be added to $M$. Every cover meets each of the disjoint matching edges, so OPT is at least $|M|$. Consequently

$$
|S|=2|M|\le2\,\mathrm{OPT}.
$$

This is polynomial on explicit graphs. On a star with two or more leaves the algorithm takes two vertices while its center alone is optimal: the ratio two is attained. For an edgeless graph both costs are zero. Maximum matching is unnecessary.

## Section 3 — Accuracy schemes

A PTAS for minimization provides ratio $1+\varepsilon$ in polynomial time for every fixed positive rational $\varepsilon$. An FPTAS additionally has running time polynomial in input length and $1/\varepsilon$. A bound $n^{1/\varepsilon}$ is not an FPTAS guarantee. For nonnegative integer costs and known polynomial bound $B$ on OPT, set $\varepsilon=1/(B+1)$. The returned integer cost is less than OPT plus one, hence exact. If $B$ is exponential in bit length, this argument does not yield polynomial time.

## Section 4 — Gap reductions

If a polynomial reduction produces minimization instances with OPT at most $a$ for yes-inputs and OPT greater than $b$ for no-inputs, with $b\ge\rho a$, a ratio-$\rho$ algorithm distinguishes them by testing its feasible cost against $\rho a$. Ordinary exact reductions need not preserve approximation gaps. PCP-based hardness uses problem-specific gap constructions, not NP-hardness alone.

## Section 5 — Guarantees versus benchmarks

A worst-case ratio is a universal bound on loss, not a prediction of typical quality. A heuristic can outperform a guaranteed algorithm empirically without having a proof of its own ratio.
