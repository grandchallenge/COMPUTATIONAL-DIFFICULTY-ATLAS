# C01 — What Is a Computational Problem?

**Status:** Editorial manuscript draft; not yet independently accepted.  
**Prerequisites:** Discrete mathematics and basic proof literacy.  
**Reader's question:** Before we ask whether a problem is difficult, what precisely is the task?

## 1. A question must have a contract

Imagine receiving the instruction: *Solve traveling salesperson.* You might be asked to decide whether a cheap tour exists, exhibit a tour, find the cheapest tour, or count tours under a budget. These tasks concern the same objects but demand different answers. A complexity classification applies to a **task and its representation**, not to a topic.

A computational problem therefore needs at least four things: an admissible instance, a finite representation of that instance, a specification of a correct output, and an algorithmic model against which resource use can be measured. When we say an algorithm is *efficient*, we will eventually specify which resource (time or memory), which measure of input size, and which family of inputs we mean.

**Intuition pump.** Asking "How difficult is chess?" without defining the board size and requested output is like asking "How far away is the destination?" without identifying either endpoint. A legal move in a fixed position, a winning strategy on a generalized board, and optimal play under a time budget are different computational tasks.

## 2. Strings, encodings, and length

Fix a finite alphabet \(\Sigma\), often \(\{0,1\}\). The set \(\Sigma^*\) contains every finite string over that alphabet. An **encoding** is a specified procedure representing admissible mathematical instances as finite strings. We write \(\langle x\rangle\) for the encoded representation of an object \(x\), and \(|\langle x\rangle|\) for its **input length**. An encoding must say how invalid strings and ambiguous descriptions are handled.

A number's *value* is not its binary *length*: the positive integer \(N\) ordinarily requires \(\lfloor\log_2 N\rfloor+1\) bits. Thus a method taking \(N\) steps can require exponential time in the bit length of \(N\). For example, on input the binary integer \(N=2^k\), counting from \(1\) to \(N\) performs \(2^k\) iterations despite the input requiring only \(k+1\) bits. This is the first reason to distinguish mathematical magnitude from computational size.

The precise encoding matters. In complexity comparisons we often use encodings with polynomial-time translation in both directions, including the cost of producing outputs. Such a proviso cannot be dropped: an encoding that succinctly compresses huge structures may alter complexity drastically. We will state encoding assumptions when they matter.

A single fixed input is not normally what a complexity class describes. Complexity concerns a **family** of arbitrarily large instances and how resource requirements grow with their representation length.

## 3. Five different kinds of question

A **decision problem** asks for one bit of information, yes or no. Its yes-instances form a **language** \(L\subseteq\Sigma^*\). An algorithm decides \(L\) if it halts on every input and answers yes exactly when the input lies in \(L\).

A **search problem** asks for a witness \(y\) satisfying a specified relation \(R(x,y)\), or reports that none exists. A relation's witnesses may need a prescribed representation and size bound; merely saying "find a solution" does not supply these details.

A **function problem** asks for a specified output \(f(x)\), such as an exact numerical result or canonical representation. Search can allow several correct witnesses, whereas a function assigns a designated answer.

An **optimization problem** asks to minimize or maximize an objective over feasible candidates, with conventions for infeasible instances and ties. An **associated decision question** may ask whether the optimum is at most a threshold; that does not make the original optimization task itself a decision problem.

A **counting problem** asks how many witnesses satisfy \(R(x,y)\), with a precisely bounded domain of counted witnesses. Its output may contain many bits, and a counting classification requires appropriate constraints on the relation.

These are formulations, not mutually exclusive subject areas: one underlying mathematical setting can support every one of them.

## 4. The traveling-salesperson fork

Let \(G=(V,E)\) be a complete undirected graph with nonnegative integer edge weights encoded in binary, and let a tour be a Hamiltonian cycle. For definiteness we treat the tour as undirected, so traversing it in reverse does not produce a distinct cycle.

- **Decision:** Given \((G,w,B)\), is there a tour of total weight at most \(B\)?
- **Search:** Given \((G,w,B)\), produce such a tour if one exists.
- **Optimization:** Given \((G,w)\), output a tour of minimum total weight (with any optimal tour acceptable).
- **Function:** Given \((G,w)\), output the numerical minimum tour weight.
- **Counting:** Given \((G,w,B)\), how many distinct undirected tours have weight at most \(B\)?

The classical claim that the **decision** traveling-salesperson problem is NP-complete (under the usual polynomial-time many-one reductions) is not literally a classification of the optimization or counting versions as NP-complete. Those variants have their own appropriate notions of difficulty. Chapters C04–C06 will define NP and completeness; no knowledge of those classes is required to use the present distinction.

**A small worked instance.** On four cities \(A,B,C,D\), suppose the edges around the cycle \(A\!-\!B\! -\!C\! -\!D\! -\!A\) cost \(2\) each, while the two diagonals cost \(7\) each. The tour \(A,B,C,D,A\) costs \(8\). Any different undirected Hamiltonian cycle uses two diagonals and costs \(18\). Thus the threshold question at \(B=9\) answers **yes**; the threshold at \(B=7\) answers **no**; the optimum weight is \(8\); and precisely one undirected tour costs at most \(9\). The same data furnished four different answer types.

## 5. Integer factorization and the halting question

A standard **factorization search task** receives a binary integer \(N>1\) and must produce its prime factorization, with multiplicities. Another task asks only for a nontrivial divisor when the input is composite. To specify the latter as a total task one must also say what to output on prime inputs. These formulations are closely connected but not interchangeable without stating the transformations.

Factorization is not, simply by virtue of being famous, known to be NP-complete. Its decision, search, function, randomized, and quantum resource questions must be distinguished. Later chapters will examine this carefully.

By contrast, the **halting problem** is naturally framed as a decision language: encode a program \(M\) and input \(x\), and ask whether \(M\) eventually stops when run on \(x\). An algorithm purporting to decide this language must itself halt with a correct answer on every encoded pair. The central computability result, established in C20, is that no such algorithm exists for a sufficiently expressive general model of computation. This is fundamentally different from requiring a very large running time. Here we are only setting the question, not presupposing its proof.

## 6. A boundary: promise problems

Sometimes a task is specified only on a subset \(D\subseteq\Sigma^*\) of allowed encodings. A **promise decision problem** consists of disjoint sets \(Y,N\subseteq\Sigma^*\), with \(D=Y\cup N\): on inputs in \(Y\), answer yes; on inputs in \(N\), answer no; outside \(D\), no behavior is required. This is not automatically an ordinary language decision problem unless behavior on out-of-promise inputs is fixed.

The promise is a genuine part of the task contract, not a convenient assumption that can be discarded in a reduction. Later we will distinguish reductions that preserve a promise from ones that do not.

## 7. What we may and may not conclude

At this stage we have **definitions**, not proofs of class containment or separation. A diagram placing two complexity classes near one another is not itself evidence of either equality or strict inclusion. Worst-case running time is not the same as typical running time, and theoretical asymptotics do not by themselves predict performance at a particular input size.

A fixed chess board is a finite state space; *generalized chess*, in which a parameter grows, is a family. Statements about the computational complexity of the two require different interpretations. Likewise, "TSP is NP-complete" is legitimate shorthand only when the surrounding context already fixes the **decision** formulation.

## 8. Exercises

1. **Threshold conversion.** Given an optimization task minimizing integer cost \(c(s)\), write its associated decision question using a threshold \(B\). What extra assumptions would be needed to recover an optimal witness from decision answers?
2. **Input length.** Let \(N=2^{100}\). How many bits are required to encode \(N\) in binary? How many iterations does a loop execute if it performs one iteration for each integer from \(1\) through \(N\)? Explain the difference.
3. **Spot the category error.** Critique: "Finding a shortest traveling-salesperson tour is NP-complete because TSP is NP-complete."
4. **Classification.** Classify each task as decision, search, function, optimization, or counting: (a) determine whether a graph has a path from \(s\) to \(t\); (b) output such a path; (c) count such paths restricted to be simple; (d) find a shortest path by weight; (e) output only the shortest-path distance.
5. **Promises.** Specify a task that must identify whether a binary string contains more zeros or ones, under the promise that the counts differ. Explain what happens to the task contract if equal counts are permitted.

## 9. Map update

We began with informal **topics** and a vague sense that some topics are harder than others. We now distinguish **formal families of encoded inputs and prescribed outputs**, along with the computational model and resource being measured. This is the coordinate system on which the rest of the Atlas will be built.

**Exit test.** If asked "What is the complexity of factoring?", a careful reader should first ask: Which factoring task? How is the integer represented? What output is required, and which computational resource and model are being measured?
