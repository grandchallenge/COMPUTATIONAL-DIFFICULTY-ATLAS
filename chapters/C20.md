# C20 — Decidability: Where Computation Ends

**Status:** Reviewed editorial candidate; corrections from CDA-REV-C20-002 applied; publication acceptance pending.  
**Prerequisites:** C01 on decision problems; C03–C04 on efficient algorithms and verification.

## Question: could more time solve every well-posed computational task?

Our earlier chapters distinguished polynomial-time problems from those for which we have no known fast solution. But even a staggeringly slow algorithm, given sufficiently many steps, may produce the right answer. Now we ask whether *any* algorithm exists that always stops and answers correctly.

The key transition is from resource bounds to **algorithm existence**. Undecidable does not mean “takes infinite time on all inputs.” It means no single program has the required total yes/no behavior over the full specified family of inputs.

## 1. Deciders and recognizers

Let $L\subseteq\{0,1\}^*$ be a language over effectively encoded finite strings.

A **decider** for $L$ is a Turing machine $D$ that halts on *every* input and accepts exactly the strings in $L$, rejecting all others. A language is **decidable** if such a machine exists.

A **recognizer** for $L$ accepts every $x\in L$, and never accepts $x\notin L$. On nonmembers it may either reject or continue forever. A language is **Turing-recognizable** if it has such a machine. Every decidable language is recognizable, but recognition is weaker than decision.

**Intuition pump:** A recognizer may serve as a “yes-evidence machine”: whenever its simulation accepts, you have a definitive yes. Silence may mean no, or merely that the machine has not yet found evidence. A total decider must eventually distinguish those possibilities on every input.

## 2. The halting language

Fix a conventional, effective encoding of programs and their inputs, and a universal Turing machine capable of simulating any encoded machine. Write $\langle M,x\rangle$ for an encoded pair. Define

$$
HALT=\{\langle M,x\rangle\mid M\text{ eventually halts when run on }x\}.
$$

Any invalid encodings can be handled by a fixed convention; undecidability concerns the valid instances.

**Proposition:** $HALT$ is recognizable.

**Proof.** Given $\langle M,x\rangle$, simulate $M(x)$ step by step. If the simulation halts, accept. If it never halts, continue running. All members are accepted, and no nonmember is accepted. $\square$

The absence of an observed halt after one minute, one century, or a trillion steps is not by itself a proof that the program will never halt.

## 3. A diagonal proof of undecidability

**Theorem:** The language $HALT$ is not decidable.

**Proof.** Assume for contradiction a total algorithm $H$ that, for every encoded pair $\langle M,x\rangle$, returns 1 exactly when $M$ halts on $x$, and returns 0 otherwise.

Construct a program $D$ taking as input an encoded machine description $y$. In the shorthand $H(y,y)$, the first copy of $y$ is interpreted as a program code and the second as input data; the actual computation uses an effective pair encoding $\langle y,y\rangle$:

1. Compute $H(y,y)$.
2. If $H(y,y)=1$, enter an infinite loop.
3. If $H(y,y)=0$, halt immediately.

The computation defining $D$ is legitimate: it calls a machine that we have assumed always halts, then executes one of two explicit branches.

Let $d$ be an encoding of $D$, and run $D$ on its own description $d$. If $H(d,d)=1$, $H$ predicts that $D(d)$ halts, but by construction it loops. If $H(d,d)=0$, $H$ predicts nonhalting, but by construction $D(d)$ halts. Both cases contradict the assumed correctness of $H$. Therefore no such total decider exists. $\square$

The proof exploits **self-application of a universal prediction procedure**. It does not claim that every program is mysterious or that every individual halting question is unprovable. Many particular programs can obviously be shown to stop or loop. What is impossible is a single terminating correct answerer for every encoded program/input pair.

## 4. Decidable means more than recognizable

**Theorem:** A language $L$ is decidable if and only if both $L$ and its complement $\overline L$ are recognizable.

**Proof.** If a decider exists, run it and invert the answer to decide the complement; both sets therefore have recognizers.

Conversely suppose recognizers $R_L$ and $R_{\overline L}$ exist. On input $x$, alternately simulate one step of each machine. Since $x$ belongs to exactly one of the two languages, its corresponding recognizer eventually accepts. Halt and answer accordingly. The resulting machine always terminates and decides $L$. $\square$

**Corollary:** $\overline{HALT}$ is not recognizable. Otherwise the theorem would combine recognizers for $HALT$ and its complement to decide $HALT$, contradicting the diagonal proof.

This establishes a precise distinction among “decidable,” “recognizable but undecidable,” and “not recognizable,” without any estimate of polynomial or exponential running time.

## 5. Why SAT is on the other side of this boundary

SAT receives a finite Boolean formula and asks whether any assignment satisfies it. If the formula contains $n$ variables, enumerate every one of its $2^n$ assignments, evaluate the formula, and answer yes if a satisfying assignment is found. Otherwise answer no after the final assignment.

This algorithm may be exponentially slow in the number of variables, but it always stops. Therefore SAT is decidable regardless of whether $P=NP$ is eventually resolved. By contrast, **no** universal halting decider exists under the Turing machine model. Faster hardware can reduce elapsed time for a valid algorithm; it cannot make a logically impossible total decider exist.

## 6. Why this does not make every answer unknowable

The halting language contains both easy and very difficult instances. For the program “print 1 and stop,” halting is immediate. For “loop forever,” nonhalting follows by examining the program's explicit control flow. But a procedure that handles a useful subclass of programs is not a procedure that handles every possible encoded program.

Likewise one can use a bounded simulator to answer whether $M(x)$ halts within $T$ steps. That bounded-halting question **is decidable**: simulate exactly $T$ steps and check. The unbounded question is qualitatively different, not simply the same computation with a larger $T$.

A promise restriction can change the task. For example, consider straight-line programs without loops or recursion, with all primitive operations total. Every program in this effectively recognized subclass terminates, making its restricted halting question trivial. This does **not** decide unrestricted $HALT$, because the promised input family excludes arbitrary Turing machines. C01's promise distinction applies here.

## 7. Common mistakes

**“The halting problem takes infinite time.”** There is no total correct algorithm whose time complexity could be bounded this way; some halting instances are instantly resolved.

**“If a program has not stopped, it will never stop.”** The observation of finite nontermination gives no general certificate of permanent nontermination.

**“SAT might be undecidable if $P\ne NP$.”** False. SAT's exhaustive decider exists independently of the speed of the best algorithm.

**“No machine can predict whether a program halts.”** Too strong. The theorem forbids one *universal total* predictor, not correct prediction for restricted inputs or specific machines.

## Exercises

1. Specify the inputs and output for the bounded-halting problem with time limit $T$, and prove it is decidable when $T$ is included in the finite input.
2. Reconstruct the two cases in the diagonal proof, identifying exactly which assumption is contradicted.
3. Explain why running a recognizer for a long time without acceptance does not establish nonmembership.
4. Prove the two-recognizer decidability criterion, including why alternated simulation must eventually terminate.
5. Use the previous theorem to prove $\overline{HALT}$ is not recognizable.
6. Compare SAT and HALT without using the adjective “hard”: say whether a total decider exists for each and justify your answer.
7. Give an example of a promise that changes an unrestricted halting question into a decidable question. Explain the new restriction on admissible inputs.
