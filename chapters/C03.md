## Question: when can a machine reliably answer every instance?

Suppose you have a map of intersections and one-way roads and want to know whether you can drive from a starting intersection to a destination. A route might be long and finding one by guessing could be frustrating. Nevertheless, a systematic search can check the reachable region without enumerating every imaginable route.

We use this example to introduce **P**, the class of decision problems solvable in deterministic polynomial time. The significance is not that every problem in P is fast on a particular computer, but that a single fixed algorithm answers *all* instances correctly with a specified worst-case scaling guarantee.

## Section 1 — P is a class of decision languages

Recall that a decision problem is a language $L\subseteq\{0,1\}^*$. A deterministic algorithm **decides** $L$ if it halts on every binary string and answers yes exactly for members of $L$.

**Definition.** $L$ is in $P$ if there is a deterministic Turing machine $M$ deciding $L$ and constants $c,k>0$ such that, for every input $x$ of length $n$,

$$
T_M(x)\le c(n+1)^k.
$$

Equivalently, the worst-case time is $O(n^k)$ for some fixed $k$. An algorithm that is sometimes correct, one that occasionally runs forever, or one whose claimed exponent depends on $n$ does **not** by itself establish membership in P.

An input encoding is part of the problem contract. If a string does not encode a valid graph, formula or number under the chosen convention, a decider must still have a specified, terminating response (commonly reject). This matters when turning a mathematically defined task into a total language over all binary strings.

P is a class of **decision** languages. We may informally call a function or search task "polynomial-time computable," but that is not literally membership of a function in P unless a corresponding decision language is specified.

## Section 2 — Directed graph reachability

A directed graph $G=(V,E)$ consists of finitely many vertices and directed edges. A *directed path* from $s$ to $t$ follows the orientation of each edge. Define the decision problem

$$
\mathrm{REACH}=\{\langle G,s,t\rangle:\text{a directed path from }s\text{ to }t\text{ exists in }G\}.
$$

Use a conventional explicit encoding, such as an adjacency list with numbered vertices and named endpoints. This representation has length at least proportional to the number of explicitly listed vertices and edges (up to encoding conventions). We can parse and validate it in polynomial time.

**Breadth-first search (BFS)** finds all vertices reachable from $s$ by repeatedly following outgoing edges of already discovered vertices.

Pseudocode:

```text
REACH(G, s, t):
    if encoding is invalid: return NO
    discovered = {s}
    queue = [s]
    while queue is not empty:
        u = remove_front(queue)
        if u == t: return YES
        for each outgoing edge (u, v):
            if v is not in discovered:
                add v to discovered
                append v to queue
    return NO
```

The "discovered" test can be implemented by an indexed Boolean array; the queue can be stored with a head pointer. A vertex is inserted into the queue at most once. When that vertex is removed, each outgoing edge is scanned once. With an explicit **indexed** adjacency-list representation, the graph-search stage takes $O(|V|+|E|)$ elementary list/queue operations after input decoding and validity checking. This is a bound for the graph-search core, not a claim that arbitrary bit-level parsing and vertex-identifier decoding also take exactly that many machine steps. Those preparatory operations remain polynomial in the explicit encoded input length.

**Correctness, soundness.** Initially $s$ is discovered and has a path of length zero from itself. Every newly discovered vertex $v$ is reached by an edge from a previously discovered $u$. By induction, each discovered vertex is reachable from $s$. If the algorithm returns YES at $t$, such a path therefore exists.

**Correctness, completeness.** Suppose a path $s=v_0,v_1,\ldots,v_r=t$ exists. The start vertex is discovered. Whenever $v_i$ is processed, the outgoing edge to $v_{i+1}$ causes $v_{i+1}$ to be discovered if it has not been discovered already. Because the finite queue eventually processes every enqueued vertex, induction along the path shows that $t$ is discovered and eventually processed. Hence the algorithm returns YES.

**Termination.** At most $|V|$ vertices enter the queue, and each finite outgoing-edge list is scanned once. The loop must stop.

Combined with polynomial parsing and bounded-size arrays, this is a deterministic polynomial-time *decider* for directed reachability. Thus $\mathrm{REACH}\in P$.

## Section 3 — A small instance with both outcomes

Let the vertices be $\{a,b,c,d,e\}$ and the directed edges

$$
E=\{(a,b),(b,c),(c,d),(a,e)\}.
$$

Starting from $a$, BFS can discover $b,e$, then $c$, then $d$, so the query $(a,d)$ is YES. Starting from $e$, no outgoing edges are available, so the query $(e,a)$ is NO. Changing the direction of the desired journey changes the answer even though the set of vertices is unchanged.

The algorithm does not need to guess all $5!$ possible vertex orderings. It stores a small set of discovered vertices and systematically processes relevant outgoing edges. If a path rather than a yes/no answer is desired, BFS can store each newly discovered vertex's predecessor; following these predecessors backward from $t$ and reversing the sequence reconstructs a valid path in polynomial time. That is a search-algorithm statement, not an assertion that the search task itself is a decision language in P.

**Special case.** When $s=t$, the path of length zero establishes YES immediately. This is not an exception to the definition of directed reachability; it is its simplest case.

A second anchor is C01's traveling salesperson problem: checking whether one *supplied* tour has length at most $B$ is efficient, but an efficient test for an arbitrary input **without a supplied tour** is not established by that observation. This gap motivates C04.

## Section 4 — Polynomial growth comes from the encoded input

The BFS complexity statement $O(|V|+|E|)$ refers to explicit graph data. Because the encoding length $n$ includes the listed vertices, edges and their endpoints, $|V|+|E|$ is polynomially bounded in $n$ under the standard representation. Its endpoint numbers contain only polynomially many bits, and arrays indexed by vertex identifiers are representable within polynomial resources.

If a graph were represented **succinctly** by a small circuit that describes exponentially many edges, the same BFS complexity as a function of the *expanded graph* would not imply polynomial time in the shorter circuit encoding. This is another reason C02's representation principle matters.

Similarly, an algorithm taking $O(N)$ steps on the value of a binary integer $N$ may be exponential in the bit length. Always state what $n$ counts.

## Section 5 — Closure of P under useful operations

**Theorem (complement).** If $L\in P$, then $\overline L\in P$.

**Proof.** Run the deterministic polynomial-time decider for $L$ and invert its output. The new machine still halts on all inputs and takes polynomial time. $\square$

**Theorem (union and intersection).** If $A,B\in P$, then $A\cup B$ and $A\cap B$ lie in P.

**Proof.** On input $x$, run the two deciders. Accept if at least one accepts (union) or if both accept (intersection). If their times are $O(n^a)$ and $O(n^b)$, the combined time is at most their sum, which is polynomial. $\square$

**Theorem (algorithm transport, preview).** If a polynomial-time procedure transforms every instance of a decision problem $A$ into an instance of $B$ while preserving yes/no answers, and $B\in P$, then $A\in P$.

**Argument.** First translate, then run the $B$ decider. The translated instance has polynomial length because the translator needs time to write it. Both stages therefore have polynomial total cost. C05 will give the full formal definition of polynomial-time many-one reduction and its proof.

These facts help explain P's robustness: polynomial-time transformations and straightforward combinations of polynomial-time deciders do not take us outside P.

## Section 6 — Why brute-force enumeration is sometimes costly

Let a Boolean formula have $m$ variables. There are $2^m$ distinct assignments. Evaluating any **given** assignment can be done in polynomial time in the formula's written length. Enumerating **all** assignments and evaluating them is a total decision procedure for SAT, but its straightforward worst-case running time is exponential in $m$.

This demonstrates **decidability**, not membership in P. We cannot conclude that SAT is outside P merely because one obvious algorithm enumerates $2^m$ candidates. There could exist a radically different polynomial-time decider; the famous P-versus-NP question remains unresolved.

At the same time, an exponential-time algorithm need not be worthless on a modest input. The central theorem-level distinction concerns worst-case scaling, not a single benchmark.

## Section 7 — Algorithms are not complexity lower bounds

To prove $L\in P$, it suffices to exhibit one correct polynomial-time decider for $L$. In contrast, to prove $L\notin P$, one must rule out **every** possible deterministic polynomial-time decider for $L$ (under the chosen model). Showing that a certain search tree is enormous or that a particular heuristic fails does not establish such a lower bound.

This asymmetry between constructing an algorithm and proving none can be efficient is central to complexity theory. We can often prove upper bounds directly while class separations remain open.

The phrase "tractable" is commonly associated with polynomial time, but it is a modeling convention, not an engineering guarantee. A procedure with bound $n^{100}$ is in the class even though it would usually be unusable. A fixed-parameter or approximate algorithm may be very effective without solving the exact worst-case decision problem within the stated class.

## Section 8 — Common mistakes

**“The class P contains only easy-looking problems.”** Membership is a theorem about algorithms, not visual impressions.

**“BFS is polynomial because it is fast on my map.”** The proof requires a finite all-input algorithm and a bound in encoded input length.

**“A fast verifier is the same as a fast decider.”** A verifier receives a claimed witness. A decider must answer without assuming a useful witness is supplied.

**“SAT uses exponential search, therefore SAT is not in P.”** The conclusion does not follow from one algorithm's cost.

**“A graph with $2^n$ vertices can always be searched in polynomial time.”** Only if the graph's explicit encoding has at least comparable size; succinct representations change the resource calculation.

**“P denotes polynomial-time optimization problems.”** P is a class of decision languages. Optimization and function formulations require their own precise complexity claims.
