# C05 — Reductions: Transporting Difficulty

**Status:** Editorial draft; independent review outstanding.

## Question

Can a solver for problem B be used to solve problem A? A reduction is a translation from instances of A to instances of B. It is directional: a solver for the target B helps solve the source A.

## Definition

For languages A and B, write \(A\le_m^P B\) if a deterministic polynomial-time function (f) satisfies

\[
x\in A\iff f(x)\in B
\]

for every encoded input x. The translation must preserve yes and no answers and be computable within the stated resource bound.

## Theorem: algorithm transport

If \(A\le_m^P B\) and \(B\in P\), then \(A\in P\).

**Proof.** Compute \(f(x)\), then run the B decider. Since a polynomial-time machine can output only polynomially many bits, the second algorithm still runs in polynomial time in \(|x|\). The equivalence gives correctness. \(\square\)

## Theorem: composition

If \(A\le_m^P B\) by f and \(B\le_m^P C\) by g, then \(A\le_m^P C\) by \(g\circ f\). Both the membership equivalence and the polynomial-time bound compose.

## Worked translation

Undirected reachability reduces to directed reachability: replace every undirected edge {u,v} by the two directed arcs u→v and v→u. There is an undirected path from s to t exactly when there is a directed path in the converted graph. The conversion costs polynomial time.

A problem B is NP-hard (for these reductions) if every language in NP reduces to B. If B also belongs to NP, it is NP-complete. Hardness is an **incoming-arrow** property; an efficient algorithm for A does not imply one for B merely because \(A\le_m^P B\).

A Turing reduction, unlike a many-one reduction, may ask its solver multiple adaptive questions. These are not interchangeable notions.

4. Explain why polynomial reduction overhead can be impractical for small inputs.
