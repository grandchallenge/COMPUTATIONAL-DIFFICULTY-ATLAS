# C01 — What Is a Computational Problem?

Status: keystone specification v0.1

## Pedagogical objective

The reader should understand that complexity belongs to a precisely formulated computational task, not to an informal topic such as "traveling salesperson" or "factoring."

## Reader-facing question

Before asking how hard a problem is, what exactly counts as an instance, an answer, and a successful algorithm?

## Core distinctions

- finite encoding vs mathematical object;
- instance size vs numerical magnitude;
- decision vs search vs function vs optimization vs counting;
- total problems vs promise problems;
- problem family vs one fixed-size instance.

## Anchor problems

- **TSP:** split immediately into decision and optimization formulations.
- **Integer factorization:** introduce as a function/search task; avoid silently converting it into an NP-complete-style decision problem.
- **Halting:** formulate as a decision language to prepare the computability branch.

## Formal payload

- alphabets, strings, encodings, and languages;
- decision problem as language membership;
- relations for search problems;
- objective functions for optimization;
- counting functions;
- polynomially related reasonable encodings;
- explicit warning that complexity claims are formulation-sensitive.

No complexity class beyond informal orientation is required here.

## Misconception obligations

M13 and foundations for M05, M12, M16.

## Figure obligations

- **F1.1** may appear only as an orientation figure, explicitly labeled as a first-order map.
- A problem-formulation fork should show one informal problem giving rise to decision, search, optimization, and counting tasks.

## Epistemic-status requirements

No open class separation should be presented as settled. Statements about "the complexity of chess," "TSP," or "factorization" must identify the formulation.

## Exercises / thought experiments

1. Rewrite an optimization problem as a decision problem.
2. Give two encodings of the same integer input and compare input lengths.
3. Spot the defect in: "TSP is NP-complete, therefore finding the shortest tour is an NP-complete problem."
4. Classify several prompts as decision/search/function/optimization/counting.

## Map update

The reader's map changes from "topics have difficulty" to "formal problem families have complexity relative to a model and resource measure."

## Exit test

The reader can explain why "What is the complexity of factoring?" is underspecified before any class name is discussed.
