# C20 — The Boundary of Computability

Status: keystone specification v0.1

## Pedagogical objective

The reader should experience undecidability as a qualitative boundary: not "too many resources," but the nonexistence of any total algorithm solving every instance.

## Reader-facing question

Are there precisely stated decision problems for which no algorithm can always halt and return the correct answer?

## Core distinctions

- decidable vs recognizable;
- finite runtime bound vs existence of any halting algorithm;
- hard vs uncomputable;
- individual machine behavior vs universal decision procedure.

## Anchor problems

- **Halting problem:** primary anchor.
- Earlier finite-resource anchors are used as contrast: SAT may be difficult, but it is decidable.

## Formal payload

Define decidable and Turing-recognizable languages.

Prove undecidability of the halting problem by a diagonal/self-reference argument with all machine/input encodings stated carefully.

Introduce the existence of decidable languages outside familiar resource-bounded classes as a bridge from complexity to computability.

Rice's theorem is previewed and proved in C21 unless the chapter flow benefits from a tightly bounded statement here.

## Misconception obligations

M09, M15.

## Figure obligations

## Epistemic-status requirements

"Impossible" means no algorithm with the specified total-correctness behavior exists. It must never be used merely as rhetoric for large runtime.

## Exercises / thought experiments

1. Separate "halts on this input" from "decides halting for all encoded machines and inputs."
2. Reconstruct the diagonal contradiction.
3. Spot the defect in "the halting problem takes infinite time."
4. Compare SAT and HALT in terms of algorithm existence, not practical runtime.

## Map update

The reader's map gains a boundary that is categorically different from all earlier resource limits.

## Exit test

The reader can explain why giving a faster computer cannot, even in principle, turn an undecidable problem into a decidable one.
