# C10 — Space as a Computational Resource

Status: keystone specification v0.1

## Pedagogical objective

The reader should understand that memory is an independent resource and that a computation may reuse a small workspace over a very long execution.

## Reader-facing question

What changes when we bound how much information an algorithm may keep at once rather than how many steps it may take?

## Core distinctions

- time vs space;
- input space vs work space;
- polynomial time vs polynomial space;
- configuration count vs simultaneous memory;
- deterministic vs nondeterministic space.

## Anchor problems

- **Directed reachability:** returns as the canonical low-space graph problem.
- **QBF/TQBF:** previewed as the principal PSPACE-complete anchor for C11.

## Formal payload

Define deterministic space complexity and PSPACE.

Establish:
- \(P \subseteq PSPACE\);
- \(NP \subseteq PSPACE\);
- configuration-based intuition for space reuse;
- Savitch's theorem at theorem/proof-sketch level:
  \[
  NSPACE(s(n)) \subseteq DSPACE(s(n)^2)
  \]
  for appropriate \(s(n)\), yielding \(NPSPACE=PSPACE\).

Do not claim \(NP \subsetneq PSPACE\); strictness is open.

## Misconception obligations

M19, M10, M15.

## Figure obligations

- tape/workspace picture contrasting elapsed steps with occupied cells;
- configuration graph for a bounded-space machine;
- map update from NP to PSPACE with equality status explicit.

## Epistemic-status requirements

The text distinguishes proved containment from unknown strictness. Any placement of EXPTIME is deferred unless the relevant theorem is introduced.

## Exercises / thought experiments

1. Construct a computation that reuses one small workspace for many iterations.
2. Explain why exponential time can coexist with polynomial space.
3. Spot the defect in a diagram that labels PSPACE simply "harder than NP."
4. Work through recursive reachability in a configuration graph.

## Map update

The reader adds a second resource axis and sees why one vertical notion of "difficulty" is inadequate.

## Exit test

The reader can explain, without class-name recitation, how an algorithm can use polynomial space while taking far more than polynomial time.
